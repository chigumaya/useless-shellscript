# シェルピンスキーのギャスケット解説

シェルピンスキーのギャスケットを生成するリスト4.17(p.108)のスクリプトについて、本文ではどのような手法が使われているか軽く紹介しただけで、あとは「本書の内容を理解していれば十分に読めるはずなのでぜひ読解に挑戦してもらいたい」で済ませた。読み解けただろうか？

ここではこのスクリプトについて解説する。

```bash
_________=sierpinski.png
__=${#?}
: /???/??/$?
___=$_
: /${___:__+__:__}??
____=${_:__+__:__}
: /${___:__+__+__:__}??
____+=${_:__+__+__:__}
______=($__)
_____=$[__<<$__$?-__]
___=$($____ \!-@ @-_<<<$__)
___+="$__ $_____ $_____"
________='((_______=__,
${__________=______[_______]^=______[_______-__],
++_______<_____&&__________}))
___+="
${______[@]}"
((++___________<_____))&&$____ . .<<<"$________">>${!?}||
$($____ \ -/:-@ \`-\{<<<"#/.@%<>") - $_________<<<"$___"'
$____ . .<<< "$________">>${!?}

```

## このスクリプトについて

かつて、Zenn に [記号だけでシェルピンスキーのギャスケットを描く](https://zenn.dev/yamaya/articles/f4ea47e5c70d64) という記事を書いた。さらにさかのぼれば、[このtweet](https://x.com/yamaya/status/1114915716640071681)(その[実行結果](https://x.com/minyoruminyon/status/1114915764987817984)がある。

これらは画像の各ピクセルの計算と横方向の繰り返しを算術式で、縦方向の繰り返しを算術式の再帰でおこなうものだった。これを縦方向の繰り返しを自己追記でおこなうように書き換えたものが本書に掲載したスクリプトである。また、以前のものは Linux (`/proc/$$`) や m4 コマンドに依存していてたがこれらを利用しないようにした。さらに  `convert` コマンドは記号化せずアルファベットのままだったのを本書ではこれも記号化している。

これらの修正の結果、もともとは1ツイートで収まるものだったスクリプトが、2倍近い503バイトまで肥大化してしまった。

自己追記のないものについては上記 zenn の記事で詳しく解説しているので、そちらも参照してほしい。

## 読みやすくする

スクリプトの1行目は単なる変数への代入だから、かならず成功して終了ステータスは`0`になり、その文字列長 `${#?}` は`1` になる。

つまり、2行目の `__=${$#?}` は変数 `$__` に`1`という値を代入している。

3行目の `/???/??/$?` は2章で何度も出てきたように、`/dev/fd/0` にマッチするワイルドカードである。

18行目と20行目の `${!?}` は変数の間接参照である。

```
$ a=b
% b=c
$ echo ${!a}
c
```

この例で、`$a` の値は `b` であり、`$b` の値は `c` だから、`${!a}` の値は `$b` すなわち `c` になる。算術式の再帰展開に似ているが、それとは異なり何度も変数展開されることはなく1回きりである。

前の行が成功する前提なので、`$?` は `0` で、よって `${!?}` は `$0` すなわちスクリプト自身である。

そのほか、変数名をわかりやすいアルファベットに変更したものが以下になる。

```bash
output=sierpinski.png
# __=1
: /dev/fd/0
s=$_
: /${s:1+1:1}??
tr=${_:1+1:1}
: /${s:1+1+1:1}??
tr+=${_:1+1+1:1}
cell=(1)
size=$[1<<10-1]
s=$($tr \!-@ @-_<<<1)
s+="1 $size $size"
main='((i=1,
${loop=cell[i]^=cell[i-1],
++i<size&&loop}))
s+="
${cell[@]}"
((++j<size))&&$tr . .<<<"$main">>$0||
$($tr \ -/:-@ \`-\{<<<"#/.@%<>") - $output<<<"$s"'
$tr . .<<< "$main">>$0
```

もちろん、これを実行しても元のスクリプトと同じ画像が生成される。

この記号化を解除したものを `omake/sierpinski-nosym.sh` に置いておいた。

## 3-8行目

`/dev/fd/0` から `e` の文字を取り出し、`/e???` のワイルドカードから `/etc` にマッチさせて `t` の文字を得る。また、`/dev/fd/0` から `v` を取り出して `/v??` のワイルドカードから `/var` にマッチさせて `r` の文字を得る。この2文字から `tr` の2文字を作り出している。

## 9行目

```bash
cell=(1)
```

配列変数 `$cell` の最初の要素に`1`をセットする。この配列は1次元セルオートマトンの状態をあらわす

## 10-12行目

```bash
size=$[1<<10-1]
s=$($tr \!-@ @-_<<<1)
s+="1 $size $size"
```

まず、10行目で生成される画像のサイズを決めている。ここでは `1<<9` つまり縦横512ピクセルの画像を生成する。

11行目では本文pp.33-34で解説した `tr` コマンドによる文字コードずらしの方法を使って `P` の文字を作っている。

さらに、12行目で文字列を付け加えて `P1 512 512` という文字列を作っている。これは 512x512ピクセルの PBM (ascii) 形式の画像ファイルのヘッダである。

この後 `$s` にシェルピンスキーのギャスケットの各ピクセルが追加されていくことになる。

## 13-20行目

```
main='...'
$tr . .<<< "$main">>$0
```

13-19行目で自己追記するコードを定義し、20行目で自分自身に追記してループに突入している。

## 自己追記ループ

自己追記されるのは以下のコードである。

```bash
((i=1,
${loop=cell[i]^=cell[i-1],
++i<size&&loop}))
s+="
${cell[@]}"
((++j<size))&&$tr . .<<<"$main">>$0||
$($tr \ -/:-@ \`-\{<<<"#/.@%<>") - $output<<<"$s"
```

最初の3行は算術式によるループで、画像の横方向のピクセルを計算している。

`${var=value}` は変数 `$var` が未定義ならば `$var` に `value` を代入し、その後 $var の値に展開される。つまり、この算術式は、

```
loop='cell[i]^=cell[i-1],++i<size&&loop'
((i=1,cell[i]^=cell[i-1],++i<size&&loop))
```

と同じである。ここに含まれる `cell[i]^=cell[i-1]` がシェルピンスキーのギャスケットを生成する Rule90 の核心である。本文 p.108 ではこれとは少し異なる式になっているが、このような変形についての説明は [Zennの記事](https://zenn.dev/yamaya/articles/f4ea47e5c70d64) を参照してもらいたい。

次の2行では、計算した横方向のピクセルを変数 `$s` に追加している。

最後の2行が終了判定で、ループの回数が縦方向のピクセルに満たない場合は `$main` を自分自身に追記してループを継続する。画像の生成が完了していれば変数 `$s` を `convert` コマンドに与えて画像を PBM から PNG 形式に変換し、指定したファイルに保存している。`$($tr ...)` が `convert` である。
